14.0Unit Map

本單元目錄

這週是整學期最關鍵的一步：你的網頁要從「只有自己看得到」變成「任何人點網址都看得到」。

應用

14.2Scenario

從家裡的廚房，搬到街上開店

到目前為止，你的網頁只在自己的電腦裡。就像在家裡廚房煮出一碗好拉麵，但客人進不來。

你的電腦
my-site 資料夾→ GitHub
雲端倉庫（放食材）→ Pages 或 Netlify
店面（端給客人）→ 一個網址
任何人都能點
「部署」就是這整段路。這週你會發現：倉庫只有一個（GitHub），但開店的方式有兩種，而且可以同時開。
14.3Vocabulary

三個新名詞

repo

倉庫。放在 GitHub 上的專案資料夾，就是雲端版的 my-site。

commit

存檔＋留紀錄。每次上傳都會記下「誰、什麼時候、改了什麼」，改壞了可以回頭找。

部署

開店。把倉庫裡的檔案變成大家都看得到的網站，會得到一個網址。

template（範本）：老師準備好的 repo。你按一下「Use this template」，就會複製一份屬於你自己的 repo，改了不會影響別人。
14.4Two Routes

兩條路線，怎麼選

路線 A · GitHub Pages

全部在 GitHub 裡完成，只要一個帳號。
網址：帳號.github.io/repo名/

路線 B · GitHub＋Netlify

GitHub 放檔案、Netlify 開店。網址可以自己取名，每次上線都有紀錄可看。
網址：自訂名稱.netlify.app

路線 A：GitHub Pages路線 B：GitHub＋Netlify
帳號GitHubGitHub（Netlify 用 GitHub 登入）
設定一次自己的 repo 要再開一次 Pages匯入 repo，兩個欄位留空
之後更新上傳到 GitHub 就自動更新
看得到上線紀錄不太直觀Deploys 頁面一目了然
限制repo 要公開免費每月約可上線 20 次
選路建議：想少記一個帳號 → 選 A；想要好記的網址、想看上線紀錄 → 選 B。兩條都開也可以，同一個 repo 不用重做。評分不分路線。

14.7Starter File

起始檔上車點③

W11–W13 沒跟上？老師的範本 repo 本身就是起始檔：已經有完整的網頁、JS 互動和自適應版面。

怎麼用

照 14.5 用 template 建好 repo 後，直接在 GitHub 網頁上點檔案 → 右上鉛筆圖示編輯，把 TODO 的地方換成你的品牌內容。

能拿到哪一級

成功上線＝最低 A 級。要到 B 級以上，需要替換成自己的原創內容並延伸。

使用起始檔不扣分。能上線，你就趕上全班了。
14.8A · Demo 2 · Route A

示範②-A　GitHub Pages

01

Settings

在自己的 repo 上方按 Settings

02

Pages

左側選單找 Pages

03

選來源

Deploy from a branch → main → /(root) → Save

04

等 1–2 分鐘

重新整理，上方出現網址

最大卡點：template 複製的是檔案，不會複製 Pages 設定。老師的範本開了 Pages，不代表你的也開了，一定要在自己的 repo 再開一次。
14.9A · Demo 2 · Route B

示範②-B　GitHub＋Netlify

01

用 GitHub 登入

到 netlify.com，Sign up／Log in 選 GitHub

02

匯入專案

Add new project（舊介面叫 Add new site）→ Import an existing project → GitHub

03

授權、選 repo

按 Authorize，清單中選你的 repo

04

兩欄留空 → Deploy

Branch：main；Build command、Publish directory 都留空

改一個好記的網址

Project configuration → Change project name，例：ramen12-s1234 → 網址變成 ramen12-s1234.netlify.app

為什麼兩欄要留空

那兩欄是給需要「先組裝」的網站用的（例如 React）。你的網站是現成的 HTML，不用組裝，Netlify 直接端出去就好。

14.10Route B Rules

走路線 B，記住三條規則

① 改好一批再上傳

每上傳（commit）一次，Netlify 就重新上線一次。免費方案每月大約 20 次，在 VS Code 確認好再一次傳。

② 有人填了就清空

如果 Build command 自動出現文字，清掉它，不然會上線失敗。

③ 被暫停就換路線

看到「production deploys are paused」：網站還在，但新改動上不去。直接在同一個 repo 開路線 A，交 Pages 網址。

Deploys 頁面是你的除錯證據：每次上線成功或失敗都有紀錄。失敗時截圖存起來，W15 和期末「除錯歷程」用得到。
14.11B · Follow Along 2

本機正常、上線破圖？九成是檔名大小寫。Logo.PNG 和程式裡寫的 logo.png 在伺服器上是兩個檔案。W15 會專門處理。
14.12Update Loop

之後怎麼更新網站

設定只做一次。之後每次修改，流程都一樣：

VS Code 修改→本機預覽確認→GitHub：Upload files
（同名檔案會被覆蓋）→Commit→1–2 分鐘後網站自動更新

小改字也可以直接在 GitHub 改

點檔案 → 鉛筆圖示 → 修改 → Commit changes。但改完記得把 VS Code 那份也同步，不然下次上傳會蓋回舊的。

樣式不見了？

Stitch 的 Tailwind 是從網路載入的（W10 那一行 <script>），沒有網路時樣式會消失，這是正常的。
