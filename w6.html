6.2Scenario

晚上 9:40 的公車站

你剛下班，只想知道十二席拉麵今天有沒有開。一手拿包包、一手滑手機，點進官網——

STEP 1

全螢幕影片自動播放

而且還有聲音，你手忙腳亂找靜音。

STEP 2

首頁找不到營業時間

關掉影片之後，畫面上只有大圖和標語。

STEP 3

點「關於我們」

往下捲、再捲……終於在第三段看到營業時間。

68%

有調查指出，約 68% 的使用者會因為體驗不好，而直接離開網站或 App。大部分的人在 Step 1 就關掉網頁，改去 Google 地圖查了。

這個網站可能做得很漂亮，但它不好用

今天要學的，就是怎麼說出「它哪裡不好用」。

6.3-1UI vs UX · 1/5

好看是 UI，好用是 UX

先用一句話分清楚：UI 是「東西」，UX 是「過程」。

UI · 使用者介面

你看到、摸到的東西

UX · 使用者體驗

你從頭到尾經歷的過程和感受

6.3-2UI vs UX · 2/5

在拉麵店裡

同一間店，UI 和 UX 各在哪裡？

UI · 使用者介面

招牌、菜單排版、餐券機按鈕

UX · 使用者體驗
找到店看懂菜單買券等位吃完離開
6.3-3UI vs UX · 3/5

換到網頁上

把拉麵店換成拉麵店的官網，道理一樣。

UI · 使用者介面

按鈕、字體、配色、圖片、版面

UX · 使用者體驗
進站找到想要的完成任務（訂位、查時間）
6.3-4UI vs UX · 4/5

做不好的時候

UI 做不好和 UX 做不好，使用者遇到的狀況不一樣。

UI · 使用者介面

字太小、顏色看不清、按鈕看起來像裝飾

UX · 使用者體驗

找不到、要繞路、做到一半放棄

6.3-5UI vs UX · 5/5

怎麼檢查好不好

UX 不是感覺，可以用「數」的方式檢查。

UI · 使用者介面

一致嗎？看得清楚嗎？主次分明嗎？

UX · 使用者體驗

完成任務了嗎？中途出錯幾次？花了多久？

6.4Both Matter

兩個都要，但不一樣

餐券機很漂亮（UI 好），但按鈕順序和牆上菜單對不起來，每次都要找半天（UX 差）。

店面陽春，但動線順、點餐快，客人照樣回頭——UX 好，不一定要 UI 華麗。

沒有 UI 的 UX，像一棟沒有門把的房子——進不去。

沒有 UX 的 UI，像一個很漂亮的門把，但看不出應該要拉門還是推門。

三個常見誤會（點一下看答案）

影片裡的拉麵店比喻，「從找到店、買券、等位到吃完離開」這整段經驗屬於？
答對了！UI 是看得到摸得到的（像餐券機按鈕），UX 是整段經歷。

6.5Design Thinking

設計思考：你其實已經在做了

設計思考＝從「使用者想解決什麼」出發。不是先打開工具配色，而是先想清楚：客人是誰？他想做什麼？

階段做什麼這門課
同理搞清楚客人是誰、在意什麼第 1 週品牌企劃
定義說清楚網站要解決哪個問題第 1–2 週企劃
發想想出要有哪些頁、哪些區塊第 3 週網站區塊
原型先做出看得到、點得到的版本第 7–11 週
測試找人實際用，看哪裡卡住，再回頭修今天、第 15–16 週
五個階段是循環：測試發現問題，就回到前面修。今天學的方法，就是「測試」用的工具。
影片檢核點 Q2・可無限次重答
這週評估別人的網站、找出卡點，屬於設計思考的哪一個階段？
答對了！第 1 週企劃是同理和定義，第 3 週畫區塊是發想，今天是測試。

6.6Five Checks

看一個網頁好不好用，看這五件事

①

視覺層級

最重要的東西，是不是最大、最先被看到？

②

閱讀動線

重要資訊，有沒有放在視線會經過的路上？

③

首屏

不往下捲，能不能知道「這是什麼、對我有什麼用、下一步按哪裡」？

★ 四大原則
④

可視性與包容

字看得清楚嗎？圖片有說明嗎？會不會突然出聲？

★ 四大原則
⑤

一致性與易尋性

同樣的功能長得一樣嗎？手機上找得到、按得到嗎？

★ 四大原則
測驗②會考：其中「對比與可視性、首屏、導覽易尋、介面一致」被稱為介面設計四大原則（標 ★ 的三個看點涵蓋這四項）。
6.7Check ① · Hierarchy

看點① 眼睛會先看：大的、粗的、對比強的

用大小、粗細、顏色、留白分出主次。試試看：左邊這張，你第一眼看哪裡？答不出來，就是沒有層級。

6.8Check ② · Reading Path

看點② 使用者是「掃」網頁，不是一字一字讀

F 型

文字多的頁面（菜單、文章）。先橫掃前兩行，再沿左邊往下 → 重點放在每行開頭。

Z 型

圖多字少的頁面（首頁、活動頁）。左上 → 右上 → 左下 → 右下 → 終點放你要他按的按鈕。

6.9Check ③ · Above the Fold

看點③ 首屏三問＋拇指熱區

首屏＝打開網頁、還沒往下捲時看到的範圍。手機的首屏比電腦小很多，所以一定要用手機檢查。

首屏要回答三個問題

  • Q1 這是什麼？（店名、品牌）
  • Q2 對我有什麼用？（今天有沒有開、賣什麼）
  • Q3 下一步按哪裡？（訂位、看菜單）

拇指熱區

單手拿手機時，拇指最好按到畫面下半部 → 主要按鈕放下面、做大一點。

6.10Check ④ · Accessibility

看點④ 不是每個人都在理想的環境、用理想的設備看網頁

文字對比

淺灰字配白底、深藍字配黑底都很難看。檢查方法：在大太陽下、或把螢幕調暗，還看得清楚嗎？

圖片替代文字（alt）

看不見的人用「螢幕報讀器」聽網頁。沒寫 alt 的圖，只會被唸成「圖片」。

不要自動播放有聲影片

公車上、辦公室、深夜——突然出聲，是讓人關網頁最快的方法。

看點⑤ 每次都要重新學，使用者會累

○ 一致

交通

✗ 不一致
首頁
訂位
菜單

  • 一致性：「訂位」按鈕每一頁都同樣顏色、同樣位置、同樣文字。換一頁就換樣子，會被當成不同功能。
  • 導覽好找：主選單最好在 5–7 個以內，用客人的話命名——「位置與營業時間」比「About」好懂。
  • 手機版：電腦版三欄並排，到手機要改成上下排；按鈕夠大、放在拇指按得到的地方。
目標：3 秒內知道該往哪裡去。

6.13Demo ①

示範①：分析十二席拉麵首頁

固定四步驟。開發者工具切手機尺寸：Chrome 按 F12 → 左上角手機圖示。

STEP 1

5 秒測試

只看 5 秒就關掉，說出你記得什麼 → 記得的就是視覺層級最高的東西。

STEP 2

首屏三問

切成手機尺寸、不往下捲，三題答得出幾題？

STEP 3

五看點掃描

照 ①→⑤ 看一輪，每一項只找最明顯的一個問題。

STEP 4

記錄

用下面的句型寫下來。

記錄句型

【看點】在【畫面哪裡】，使用者會【遇到什麼狀況】。

例：【首屏】在手機版第一眼只看到大圖，使用者會【不知道今天有沒有營業，必須往下捲找】。

影片檢核點 Q4・可無限次重答
照影片的記錄句型，哪一句是合格的問題描述？
答對了！合格描述＝看點＋畫面位置＋使用者遇到的狀況。

6.15Demo ②

示範②：用任務走一遍動線

STEP 1

定任務

寫一件使用者真的會來做的事，要具體——「查今天幾點開門」，不是「逛網站」。

STEP 2

數步數

從進站開始，每點一次、捲一次、打一次字都算一步。

STEP 3

找卡點

哪一步讓人猶豫、找不到、要回頭？

判斷句型

「B 版比較合理，因為完成『查營業時間』只要 0 步，而且不用猜資訊藏在哪個選單裡。」

有任務、有步數、有卡點，就是有依據。

兩個好用的經驗法則：3 次點擊內找到想要的；別讓我思考——好的介面讓人不用停下來想「這要按哪裡」。
影片檢核點 Q5・可無限次重答
影片裡「查今天幾點開門」的 A 版動線共幾步？B 版為什麼比較合理？
答對了！判斷依據是步數和卡點，不是好不好看。
再想想看。回頭看一下這一頁的重點，再選一次。
