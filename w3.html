3.0Unit Map

本單元目錄

從這週開始，HTML 正式登場。但這門課的教法不是「從零手刻一個網頁」，而是「先學會拆解、看懂，再小幅修改」——今天用 vscode.dev 開瀏覽器就能動手，不用裝任何軟體。

3.1Read, Not Write

這週的教法：拆解，不是手刻

這門課的 HTML/CSS 教學有一個明確的原則：教你「讀」，不要求你「寫」。任何要你從零刻出一整個頁面的題目，都不是這門課的標準。

你會做的事

拆解既有頁面

打開一個真實網站或範例檔，對照畫面找出「哪一段程式碼負責哪一塊畫面」。

你不會被要求的事

從零手刻一整頁

不需要背語法、不需要憑空生出一個網頁——看得懂、能小幅修改，就達標。

今天用什麼工具：瀏覽器版的 vscode.dev，不用安裝，直接打開就能編輯、預覽 HTML。請用 Chrome 或 Edge 開啟（僅支援 Chromium 系瀏覽器），桌面版 VS Code 留到第 11 週再裝。
3.2Ramen Template

十二席拉麵：標準範本

這學期會反覆看到同一個案例——「十二席拉麵」。從品牌企劃、HTML 拆解範例到之後的測驗題目，全部用同一條故事線，不會突然換成陌生的抽象範例。今天要操作的網頁語法，也是延續這個範本產生的。

標準範本用 5 個 <section> 把一個網頁拆成 5 塊內容區——例如品牌故事、菜單、營業資訊、空間介紹、交通位置。你的網站不一定要照抄這個切法，但可以用同樣的邏輯，把自己的企劃拆成「一個 <section> 負責一個主題」。

看範本的重點：不是背它怎麼寫，而是練習回答「這個 <section> 在畫面上對應到哪一塊」——這正是討論①要交的東西。接下來就用這個範本，實際跑一次從提示詞到網頁的完整流程。
3.3Prompt to Page

從提示詞到網頁：Gemini + vscode.dev 實戰

延續第二週你自己修改過的「助教 Agent」提示詞，今天實際操作一遍：從貼提示詞、產生網頁語法，到存成檔案、打開預覽，走完整條路。

STEP 1

貼提示詞給 Gemini

把第二週修改好的「助教 Agent」提示詞貼到 Gemini，送出後會產生一整段網頁語法（HTML 程式碼）

STEP 2

複製到記事本

把 Gemini 產生的程式碼整段複製，貼到記事本（Notepad／文字編輯器）

STEP 3

另存為 .html 檔

存檔時檔名結尾改成 .html（例如 index.html），存檔類型選「所有檔案」

STEP 4

用 vscode.dev 開啟預覽

打開 vscode.dev，用 Open Folder 選擇檔案所在資料夾，就能在編輯器裡看到並預覽這個網頁

常見狀況：記事本存檔預設副檔名是 .txt，如果沒有手動改成 .html 或選「所有檔案」，瀏覽器會把它當純文字打開而不是網頁。vscode.dev 每次重新整理都要重新授權資料夾，這是正常現象。
今天不用做的事：不需要看懂 Gemini 產生的每一行程式碼，重點是走完「提示詞 → 語法 → 檔案 → 預覽」這個流程，看懂結果長什麼樣子。
3.4HTML Skeleton

HTML 基本結構速查

剛剛用 vscode.dev 打開的網頁檔案，原始碼第一眼看到的骨架都長這樣。對照著你自己產生的那份檔案，一起認得這幾行。

<!DOCTYPE html>

宣告這份文件使用的 HTML 版本，永遠放第一行

<html>

網頁的根元素，包住整份網頁最外層

<head>

瀏覽器看得到、畫面看不到：標題、字型、CSS 連結…

<body>

畫面上實際看得到的所有內容都在這裡

標籤沒封閉會怎樣：忘記寫 </div> 這類收尾標籤，瀏覽器不會報錯，但後面的內容排版常會整個跑掉——這是拆解練習時最常見的踩雷點。
3.5Tag Reference

常見標籤速查卡

拆解網站時，這幾個標籤出現的頻率最高，先把它們的用途記熟。

<h1>～<h6>

標題，數字越小字級越大越重要

<p>

一個段落

<br>

強制換行，沒有結尾標籤

<ol>／<ul>／<li>

有序／無序清單與清單項目

<table>

表格：<tr> 一列、<td> 一格

<img>

插入圖片，靠 src 指定路徑

<a>

超連結，靠 href 指定去哪裡

<strong>／<em>

加粗強調／斜體強調

3.6Tag Detail I

標籤細看①：meta、br、p

速查卡看過一輪之後，這裡把幾個容易搞混或容易忽略的標籤，配上「十二席拉麵」的實際程式碼展開講。

<meta> 元素

meta = metadata，設定「瀏覽器看得到、畫面看不到」的頁面資訊；常見用途：文字編碼、手機縮放比例、頁面描述；全部放在 <head> 裡面，沒有結束標籤。

<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<meta name="description" content="十二席拉麵，一人一碗，深夜營業">

<p> 段落

一個 <p> 是「一整個段落」，瀏覽器會自動在段落上下留一點空白；語意上代表一則獨立的敘述。

<p>獨立單人座位，無須社交互動</p> <p>安心吃一碗熱湯</p>
畫面呈現

獨立單人座位，無須社交互動

安心吃一碗熱湯

<br> 換行

在文字「中間」強制換行，不是另起一段；沒有結束標籤；該用 <p> 分段的地方不要濫用 <br>。

<p> 獨立單人座位<br> 無須社交互動<br> 安心吃一碗熱湯 </p>
畫面呈現（同一段落內換行）

獨立單人座位
無須社交互動
安心吃一碗熱湯

p vs br 差異圖解

<p><p> 兩段之間，瀏覽器自動留白（段落間距）；<br> 只是硬換行，沒有那段留白——這就是為什麼列地址、列座位這種「同一件事的三行」常用 <br>，而不同主題才分 <p>。

<p>A</p><p>B</p>

行 A

行 B（間距較大）

A<br>B

行 A
行 B（緊貼）

3.6Tag Detail II

標籤細看②：註解、有序／無序清單

這一頁把「寫給人看」的註解，跟兩種常被搞混的清單標籤一次講完。

<!-- --> 註解

寫給「人」看的說明，瀏覽器不會顯示在畫面上；標記「這一段在做什麼」，方便自己或別人維護；也能暫時「關掉」一段程式碼，不用真的刪除。

<!-- 區塊二：今晚吃什麼 --> <section class="section"> <h2>今晚吃什麼</h2> <!-- <p>豚骨湯底</p> --> <p>每日精選豚骨與雞白湯底</p> </section>

<ul> 無序清單

沒有順序，用項目符號（●）標示；適合「彼此平行、順序不重要」的項目，例如特色列表。

<ul> <li>獨立單人座位</li> <li>深夜營業</li> <li>豚骨與雞白湯底</li> </ul>
畫面呈現
  • 獨立單人座位
  • 深夜營業
  • 豚骨與雞白湯底

<ol> 有序清單

有順序，自動編號（1. 2. 3.）；每個項目都放在 <li> 裡面；順序有意義時用 <ol>，像是步驟、排名。

<ol> <li>點餐機投幣、選餐</li> <li>取票、找空位入座</li> <li>入座後切換手機靜音模式</li> </ol>
畫面呈現
  1. 點餐機投幣、選餐
  2. 取票、找空位入座
  3. 入座後切換手機靜音模式

ul vs ol 差異圖解

同樣三個 <li>，外層標籤換成 <ol> 就自動編號、換成 <ul> 就變項目符號——內容完全不用改，這就是「語意標籤決定呈現方式」的最好示範。

<ul>：順序不重要
  • 項目 A
  • 項目 B
<ol>：順序有意義
  1. 步驟一
  2. 步驟二
3.6Tag Detail III

標籤細看③：<table> 表格結構

表格是拆解「營業時間」「價目表」這類資訊時最常遇到的結構，一次把它的組成規則講清楚。

組成元素

<table>：整張表格的外框　<tr>：一「列」（table row）　<th>：標題格，通常粗體置中　<td>：內容格（table data）

結構規則

<table> 裡面放 <tr>；每個 <tr> 裡面放 <th> 或 <td>；第一列通常放 <th> 當欄位標題。

時段營業狀態
22:00 - 01:00座位充足
01:00 - 04:00可能候位
對應的程式碼：<table><tr><th>時段</th><th>營業狀態</th></tr><tr><td>22:00 - 01:00</td><td>座位充足</td></tr></table> ——每一列的儲存格數量要對齊，欄位標題與內容才不會錯位。
3.6Tag Detail IV

標籤細看④：<img>、<a>

這兩個標籤都帶屬性（attribute），拆解時要連屬性一起看，才知道圖片來源、連結去哪。

<img> 圖片屬性

src 是圖片來源路徑；alt 是圖片說明文字，載入失敗時顯示，也是螢幕報讀器會念出來的內容，無障礙必備；沒有結束標籤。

<img src="images/seats.jpg" alt="12個獨立單人座位">

<a> 超連結屬性

href 是連結目標，可以是別的網站，也可以是同一頁面的某個區塊（用 #id）；target="_blank" 讓連結在新分頁打開。

<a href="https://maps.app.goo.gl/xxxx" target="_blank">開啟地圖</a> <a href="#map">查看店址</a>
3.6Tag Detail V

標籤細看⑤：<strong>、<em> 文字強調

這兩個標籤常被誤會成「純粹的外觀效果」，其實它們是語意標籤——先講語意，瀏覽器才順便給預設樣式。

<strong> 重要

語意上「很重要」，預設會粗體顯示——不是為了讓字變粗才用它，是先確定內容重要，樣式才跟著來。

<p><strong>今晚 12 席全開</strong></p>
畫面呈現

今晚 12 席全開

<em> 強調語氣

語意上「加強語氣」，預設會斜體顯示——朗讀軟體念到這裡，語氣也會不一樣，不只是視覺效果。

<p><em>建議提早入座</em></p>
畫面呈現

建議提早入座

語意 vs 外觀 圖解

同樣是「看起來粗體」，<strong> 是語意上真的重要；如果只是想要字變粗但沒有「重要」的意思，正確做法是用 CSS（font-weight:bold），而不是濫用 <strong>——這是「標籤該不該用在這裡」最常考的觀念。

正確：語意上重要

<strong>今晚 12 席全開</strong>

只是想要粗體效果

改用 CSS：style="font-weight:bold"

3.6Tag Detail VI

CSS Box Model 與本週標籤綜合範例

最後補一個 CSS 的預告知識，再把這週學到的標籤兜在一起看一次完整範例。

CSS Box Model（盒子模型）

由內而外：content（內容）→ padding（內邊距）→ border（邊框）→ margin（外邊距）。怎麼讀：在開發者工具點一個元素，右下角就會秀出這四層目前的數值。下週會用到：調整 padding／margin 的數值，就是「排版變好看」最常做的事。

margin 外邊距
border 邊框
padding 內邊距
content 內容

本週標籤綜合範例

<section class="hero-section"> <h1>十二席拉麵</h1> <p>獨立單人座位<br>無須社交互動</p> <p><strong>今晚 12 席全開</strong>， <em>建議提早入座</em></p> <a href="#map">開啟地圖</a> </section> <ol> <li>點餐機投幣、選餐</li> <li>取票、找空位入座</li> </ol>

檢核點今天正式上線

從這週開始，影片裡會出現內嵌檢核點——這是「觀看分數 20%」的計分依據，不是看播放進度。

規則

可以無限次重答

規則

答對就算通過

規則

不會記錄你答錯過幾次

規則

答錯不倒扣

為什麼這樣設計：檢核點是為了確認你真的看過、聽懂內容，不是用來為難人的關卡——答不出來就回去重看那一小段，不會影響分數。
