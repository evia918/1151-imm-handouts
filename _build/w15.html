15.2Mindset

除錯像看醫生：先問症狀，再開藥

網站壞了，最常見的反應是「整個重做」或「把整份檔案丟給 AI」。這就像頭痛就去開刀。

① 描述症狀

哪一頁、哪個區塊、手機還是電腦、看到什麼。

② 查最可能的原因

照下面的清單，從第一項往下查，常見的先排除。

③ 一次只開一種藥

一次只改一處，上傳後確認。好了就停，沒好再換下一個原因。

除錯清單：兩條路線共通

症狀第一步檢查
404／找不到頁面index.html 是否在 repo 最外層、檔名是否全小寫

15.4Checklist · Route A

路線 A：GitHub Pages 專屬

GitHub Pages
症狀第一步檢查
網址打不開自己的 repo › Settings › Pages 有沒有開（template 不會複製這個設定）
404網址有沒有少了 /repo名/；分支是否選 main、資料夾 /(root)
Pages 選項是灰的repo 是不是設成 Private（免費帳號要 Public）
想看上線有沒有成功repo 上方 Actions 分頁，綠勾＝成功、紅叉＝失敗
15.5Checklist · Route B

路線 B：Netlify 專屬

GitHub＋Netlify
症狀第一步檢查
Deploy failed（紅色）Deploys → 點那一次紀錄看 log；多半是 Build command 被填了東西 → 清空後重新部署
網站空白或 404Publish directory 是否指到 index.html 所在的資料夾（在最外層就留空）
production deploys are paused當月額度用完或平台問題。網站仍在線，改用路線 A 交網址，截圖存證
上傳了但沒有新的部署紀錄Netlify 連結的是不是這個 repo、這個分支
Deploy log 是現成的除錯證據：失敗那次和修好那次各截一張，就是期末「除錯歷程」最好的素材。
15.6Pair Test

互換測試：當彼此的第一位客人

自己的網站自己最熟，所以最看不出問題。交換網址，用「第一次來的客人」的眼睛看。

  • 用手機打開對方網址，給自己一個任務（例：「查營業時間」）
  • 數數看用了幾步、哪一步卡住
  • 換電腦再看一次，比較兩者差在哪
  • 寫下至少 2 個問題，交給對方
# 問題清單格式（一個問題一行）
在哪裡：手機版，首屏
看到什麼：「開啟地圖」按鈕在畫面外，要往下滑
屬於哪一類：W6 看點③ 首屏三問
建議：按鈕移到店名下方
不能寫「還不錯」「怪怪的」：要說出位置、現象，最好用上 W6 的看點名稱。
